# Embedded Learning Hub Sync 1.0.3

Obsidian 桌面端与手机端双向同步插件。将本目录中的 `main.js`、`manifest.json` 和 `styles.css` 放入每台设备 Vault 的 `.obsidian/plugins/embedded-learning-hub-sync/` 文件夹，然后分别在 Obsidian 的「设置 → 第三方插件」中启用。不需要 Obsidian Sync 或任何付费同步订阅。

## 1.0.3 更新：修复点号开头标题导致的隐藏文件冲突

- 对以 `.` 开头的课程标题、课时标题和其他同步笔记标题，自动在磁盘文件名最前面添加 `笔记-` 前缀，避免生成 Obsidian 默认隐藏的 dotfile/dotfolder。
- frontmatter 中的 `title` 与笔记正文保持原样，不改变学习网站上的标题或内容。
- `writeMarkdown()` 增加最后一道文件名可见性检查，即使其他代码传入点号开头的 Markdown 文件名，也会转换为可见文件名。
- 首次同步时检查旧版本按原始点号标题生成的隐藏路径；如发现 `elh_type` 和 `elh_id` 匹配的旧文件，会通过 `vault.adapter` 读取，将内容恢复为可见 Markdown 笔记，再把旧隐藏文件移动到 Vault 根目录旁的 `点号文件备份` 文件夹。
- 若隐藏笔记与已存在的可见笔记内容不同，会先创建同步冲突副本；不会静默覆盖任一版本。无法安全归档时保留原隐藏文件并显示提示。

## 1.0.2 更新

- 新增「检查和整理重复同步 ID」命令，以及设置页中的「扫描并整理」入口。
- 点击「现在同步」遇到重复 ID 时，会自动打开诊断面板并列出完整文件路径。
- 按组显示所有重复笔记、内容是否逐字节一致，并提供各版本正文预览和打开按钮。
- 可选择要保留的正式同步笔记；其他副本会原样移动到同步根目录之外的 `Embedded Learning Hub - 重复ID备份/`（若同步根目录改名，备份目录名也会相应变化）。
- 整理前会重新读取并校验每个文件的 `elh_type` 和 `elh_id`；如文件身份已变化，会停止整理。
- 不会自动合并不同内容，不会删除重复笔记，也不会覆盖所选保留文件。

## 首次连接

1. 确认学习网站已部署 V19 或更高版本，并在网站中登录现有 Supabase 账号，等待一次云同步完成。若你已经在使用 V19/V20，无需重新部署网站，只需更新 Obsidian 插件。
2. 在电脑和手机各自的插件设置中填写同一 Supabase Project URL 和公开 publishable/anon key。
3. 分别使用学习网站已有邮箱和密码登录；每台设备会把自己的刷新令牌保存在本机 Obsidian 存储中。
4. 两台设备分别运行「现在同步学习网站与 Obsidian」。

插件程序需要在每台设备各自安装一次；学习内容由现有 Supabase 在网站与 Obsidian 之间同步。可将 `Embedded Learning Hub/` 加入其他文件同步服务的排除列表，避免另一套文件同步工具与本插件同时写入。

资源收藏笔记需要填写有效的 `http://` 或 `https://` 链接后才会同步。首次同步会在 `Embedded Learning Hub/` 创建 `知识库/`、`学习记录/`、`课程笔记/` 和 `资源/` 四个目录。插件只管理这个根目录内带有 `elh_type` frontmatter 的 Markdown 文件。

命令面板还提供新建知识卡片、学习记录、资源收藏、课程笔记，以及从云端课程列表中选择课程后新建课时笔记的命令。课程笔记还同步阶段名称与学习目标。Vault 中独立存放的图片/PDF 等二进制附件不会作为附件文件单独上传；同步的是 Markdown 正文和工作区字段。

## 自动同步

- Obsidian 启动、Vault 文件创建/修改/删除/重命名、网络恢复、应用回到前台时触发同步。
- 应用处于前台时按设置的 30–900 秒间隔检查云端，默认 90 秒。
- 手机应用进入后台后，操作系统可能暂停插件；再次打开或回到前台会继续同步。

## 重复同步 ID 诊断与整理

发生「发现重复的同步 ID」时，不需要手动搜索整个 Vault：

1. 在 Obsidian 中点击插件设置里的「扫描并整理」，或在命令面板执行「检查和整理重复同步 ID」。
2. 诊断面板会按 `type:id` 分组，列出该组的全部 Markdown 文件路径，并标明文件内容是否完全一致。
3. 展开预览并打开文件比较，选择要保留为正式同步笔记的那一份。
4. 点击归档并确认。其余文件将原样移动到同步根目录之外的 `重复ID备份` 文件夹，不会删除；它们不再参与同步。
5. 所有重复组整理完后，重新执行「现在同步」。

## 路径冲突与隐藏文件保护

- 更新文件前会核对 Markdown frontmatter 中的 `elh_type` 和 `elh_id`，确认属于同一条同步记录才原位修改。
- 若目标文件名已被其他笔记占用，或目标位置被同名文件夹占用，会使用包含稳定 ID 摘要的备用文件名，不覆盖原文件。
- 若同步目录中的某一级目录名称被普通文件占用，会改用 `--ELH` 备用目录；若同步根目录本身与文件冲突，则提示更换根目录或重命名该文件。
- 文件名或标题以句点开头（例如 `.data复制、.bss清零与C对象初值`）时，插件会在 Vault 中使用 `笔记-.data复制、.bss清零与C对象初值` 这样的可见文件名；frontmatter 标题仍保持原样。
- 升级后首次同步会自动检查旧版点号路径。如果找到匹配的旧隐藏笔记，会先恢复到可见路径，再把旧文件原样移到 Vault 根目录旁的 `Embedded Learning Hub - 点号文件备份/`。请不要手动删除备份目录，确认新笔记正常同步后再决定是否清理。
- 旧隐藏文件与已有可见笔记的内容不一致时，会生成冲突副本供比较；无法访问或归档的隐藏文件会保留原位并明确提示。

## 冲突与删除

同步使用稳定 `elh_id` 和云端 revision。若同一条内容在网站和 Obsidian 同时修改，插件保留本机版本到 `_同步冲突/`，同步笔记按云端版本恢复；请人工合并冲突副本。删除同步笔记会删除网站对应条目；删除课程会连同其课时、完成状态和课时编辑一起移除。删除前请先备份网站工作区 JSON。

## 安全和兼容性

- 使用 Supabase 用户会话及现有 RLS，不需要新表或额外数据库权限。
- 只使用公开 publishable/anon key；禁止使用 `service_role` 或 `sb_secret_`。
- 登录密码只用于请求认证，不保存；刷新令牌保存在本设备 Obsidian 本地存储中。
- 仅使用 Obsidian API、DataAdapter（仅用于迁移 Vault API 无法索引的旧 dotfiles）、`requestUrl` 和 Web API；没有依赖 Node.js 文件系统或 Electron，`isDesktopOnly` 为 `false`。
- 插件尚未发布到 Obsidian 社区插件目录，当前是免费手动安装包。将来如提供公开 GitHub 仓库，可使用 BRAT 进行免费分发和更新；这与学习内容同步机制相互独立。
- 图片等复杂富文本在 Markdown 中编辑后可能需要重新排版；未编辑的原始 HTML 会通过隐藏注释保留。
